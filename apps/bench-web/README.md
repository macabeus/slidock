# @slidock/bench-web

The bench results UI (`bench/README.md`, The bench UI): Overview, Explorer, the row drawer
(oracle, render, heatmap and the golden render in five compare modes), Compare, Parity (B and C against the
golden reference), Fonts (the fonts lane), Effects (the motion lane) and Methodology. All state is in the URL fragment
(`src/state/url.ts`).

## Two builds

- `vite build` → `dist/`: the app `slidock-bench ui` serves. It reads the API below, relative to the page.
- `vite build --mode report` → `dist/report/index.html`: one self-contained file. Its head holds an empty data slot,
  `<script type="application/json" id="slidock-bench-data">__SLIDOCK_BENCH_DATA__</script>`; `slidock-bench report`
  replaces that slot element with one holding a `slidock-bench-report@1` payload (`src/data/report.ts`), every `<`
  written as `\u003c` (`src/data/inline.ts`). The build fails unless the marker appears once in the page, inside the
  slot. `SLIDOCK_BENCH_REPORT_DATA=<file.json>` (or `sample`) fills it at build time.

`pnpm build` runs both, the app first.

## API (GET only)

| Path                         | Answer                                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `api/status`                 | `Status` (404: unknown HEAD)                                                                                                     |
| `api/runs`                   | `RunsIndex`                                                                                                                      |
| `api/runs/<key>/results`     | `Results` (404: collected)                                                                                                       |
| `api/runs/<key>/rows/<row>`  | `RowDetail` (404: only the record is known)                                                                                      |
| `api/runs/<key>/parity`      | `ParityView` (404: no report)                                                                                                    |
| `api/png/<key>/<row>/<kind>` | the row's `oracle`, `render`, `heatmap`, `golden` or `golden-diff` PNG, or a motion row's `start`, `mid`, `end` or `still` frame |

Path segments are URL-encoded (row ids hold `:`, `#` and `@`). `latest` and `baseline` are resolved against the runs
index in the page. The types are the ts-rs declarations in `src/schema` (generated by `slidock-bench-schema`).

## Development

- `pnpm dev`: the dev server with a mock of the API (`mock/`) over the schema crate's synthetic bench
  (`crates/slidock-bench-schema/tests/data`), with generated slide images.
- `pnpm test`: Vitest and Testing Library over the view logic, URL state, data sources and every view.
- `pnpm screenshots <dir> [report.html]`: every view in both themes (and phone width) through headless Chromium.
- `pnpm exec playwright test --config scripts/e2e/e2e.config.ts`: the design rules (`packages/ui/src/audit.ts`) on
  every view over the dev server's mock API, with the dev server's HMR socket held open by a stub in every page
  (`holdDevServerSocket`). Its ports are `SLIDOCK_BENCH_E2E_PORT` (4320) and `SLIDOCK_BENCH_E2E_BROWSER_PORT` (3557);
  a server already on a port stops the run unless `SLIDOCK_E2E_REUSE=1` reuses it.
